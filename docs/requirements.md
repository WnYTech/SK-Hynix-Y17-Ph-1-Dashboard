# 요구사항 추적표

작성 기준: 2026-10-01. 사용자가 제공한 이미지 3장(추가 요구사항, ARC LMS, M14N Acell LogViewer) 및 전달받은 협의 내용을 함께 반영했습니다.

최신 작업 지시: **검색결과에 사용할 더미 데이터 300만 건을 생성·적용합니다.** 기존의 더미 제외 지시를 대체합니다. M14N Acell LogViewer와 ARC LMS의 분리, 왼쪽 내비게이션, 확대된 글씨와 SK hynix 색상은 유지합니다. 두 프로그램은 로컬 SQLite의 동일한 300만 행을 각각의 검색조건과 컬럼으로 조회합니다. 운영 ES 연동과 전체 로그 다운로드 실행기는 여전히 후속 범위입니다.

더미 데이터에서 서버 검색·커서 페이지 이동·행 선택·S/E/G 상세·ARC 연관검색을 구현하고 검증합니다. 아래 표의 운영 데이터·권한·스키마 연동 제약은 그대로 적용됩니다. 구현 상세는 [더미 데이터](dummy-data.md)를 확인하세요.

납기 목표: **2026-10-14(수)**. 제공 채널은 지정 GitHub 저장소이며, 외부 공개 저장소 접근 및 고객 Contributor 방식의 전달을 전제로 합니다. 계정 초대, 저장소 공개 설정 변경, 실제 반입·배포는 이번 프레임 작성에 포함하지 않습니다.

## 우선순위 및 범위

1. 생산 시스템별 / 로그 종류별 **기간 지정 조회와 다운로드**. 수백 MB 로그에서 발생하는 타임아웃이 우선 해결 대상입니다.
2. ELIS의 Space 구분과 별개로 **허용된 연관 시스템의 로그를 함께 탐색**하는 흐름.
3. 두 기존 프로그램을 왼쪽 메뉴로 구분해 제공하는 이식성 높은 웹 프레임.

사업 측 의견은 기존 LMS 모든 기능의 필수 재현 여부와 웹 유지보수 범위를 먼저 합의해야 한다는 것입니다. 이미지의 ‘파악된 기능 필수 구현’ 문구만으로 최종 범위가 확정되었다고 간주하지 않습니다. 이 문서는 프레임과 추후 연동·협의 항목을 분리합니다.

## 프로그램별 화면

왼쪽 메뉴의 **M14N Acell LogViewer / ARC LMS**로 구분합니다. 각 프로그램은 독립된 조회창, 검색조건, 선택·상세 상태와 배치를 유지합니다. 다운로드·저장조건·연결 상태 메뉴는 공통이며, 저장조건을 불러오면 해당 프로그램의 새 조회창이 열립니다.

| 구분                       | M14N Acell LogViewer                                                                                                                      | ARC LMS                                                                              |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 공통 검색조건              | Time, Fab, System, Process, Core/Biz                                                                                                      | 동일                                                                                 |
| 기본 검색조건              | G 트랜잭션 ID, G 트랜잭션 SEQ, 트랜잭션명                                                                                                 | 트랜잭션 키, SEQ, 트랜잭션명                                                         |
| 상세 검색조건              | E/S 트랜잭션 ID, 서버, 클래스명, 로그 종류, OR, AND                                                                                       | 클래스명, 로그 종류, OR, AND, Full Text                                              |
| 로그 종류                  | 실제 메타데이터 기반 드롭다운                                                                                                             | 공백으로 구분한 텍스트 입력                                                          |
| 트랜잭션 연관검색 체크박스 | 없음                                                                                                                                      | 제공                                                                                 |
| 상세 탭                    | 단일 로그 / 서비스(S) / 이벤트(E) / 글로벌(G)                                                                                             | 단일 로그 / 트랜잭션 전체 로그                                                       |
| 결과 컬럼                  | No, Datetime, 시스템, 프로세스, 서버, 로그 종류, 트랜잭션명, 클래스명, G 트랜잭션, G SEQ, E 트랜잭션, S 트랜잭션, LOT, EQP, 소요(ms), MSG | No, Datetime, 트랜잭션명, 서버, SEQ, 로그 종류, 클래스명, 트랜잭션 키, LOT, EQP, MSG |
| 전체 시스템 검색           | G 트랜잭션 ID 필수                                                                                                                        | 트랜잭션 키 필수                                                                     |
| 글씨                       | 입력 16px, 라벨·결과 컬럼·상세 탭 14px                                                                                                    | 동일                                                                                 |

ARC 원본에는 G ID 검색란이 없으므로 전체 시스템 조회는 ARC 트랜잭션 키를 기준으로 구성했습니다. 실제 G ID 대응 여부와 시스템 간 키의 유일성은 매핑 확인이 필요합니다. G ID와 ARC 키, 일반 SEQ와 G SEQ는 서로 다른 필드로 유지합니다.

검색·다운로드 API의 `program`으로 프로그램을 구분하며, 해당 화면에 없는 조건은 전달하지 않습니다. 기존 저장값은 명시된 프로그램 또는 이전 `profile`을 우선 사용합니다. 둘 다 없는 저장값은 G ID 없이 ARC 전용 조건(키/SEQ/Full Text)이 있으면 ARC로, 그 외에는 Acell로 복원합니다. 입력값은 보존하되 화면에 없는 필드는 검색에서 제외합니다.

ARC 이미지의 `EOP`, Acell 이미지의 `EQP` 표기를 공통 `EQP`로 가정했습니다. 실제 의미가 서로 다르면 필드를 분리해야 합니다. 제목 없는 컬럼에는 임의 의미를 부여하지 않았습니다.

2026-10-02 사용자 확인: 두 프로그램의 행 강조 기준은 모두 **트랜잭션명**입니다. 이름의 앞뒤 공백을 제외하고 대소문자를 구분해 전체 문자열을 비교합니다. 선택 셀은 로그 ID와 컬럼으로 식별한 한 개만 노랑으로 강조하고, 같은 트랜잭션명의 행은 분홍으로 강조합니다. 두 색상은 구분하여 직접 변경할 수 있습니다. 집계와 모아보기는 현재 페이지가 아닌 검색결과 전체에 적용합니다. 강조와 선택은 페이지 이동 및 호버에도 유지합니다. S/E/G 상세 탭과 연관검색의 ID 조회 조건은 별도로 유지합니다.

## 검색결과 추가 기능

- 모든 결과 컬럼의 서버 정렬. SEQ·G SEQ·소요 시간은 수치 순서, 동률은 로그 ID로 정렬합니다.
- 머리글 드래그 및 컬럼 설정의 이동 버튼. 순서·컬럼 너비·강조 색상을 프로그램별로 저장합니다. 경계 드래그와 좌우 방향키로 너비를 조절하고 더블클릭으로 초기화합니다.
- 검색결과 전체의 동일 트랜잭션명 행 수, 선택 셀 수(0 또는 1), 두 조건의 합집합 행 수 집계. 모아보기는 같은 범위에서 필터한 뒤 페이지를 나눕니다.
- 전체/강조 행 보기 전환, 선택 해제, 처음·이전·번호·다음·끝 페이지 및 번호 직접 입력.
- 최대 1,000행 중 화면 주변 30행만 렌더링하고, 최근 6페이지를 제한적으로 재사용합니다.

## 연동 전에 필요한 정보

- Elasticsearch / Kibana 버전, 접속 경로, 인증 방식, 인덱스 또는 alias 목록.
- 운영 로그와 동일한 스키마의 비식별화 샘플, 시간·MSG·S/E/G ID·ARC 키 매핑.
- Fab / System / Process / Core·Biz / 로그 종류 코드표와 선택값 종속 규칙.
- 시스템 간 조회 권한과 Space별 접근 정책. 웹에서 권한을 우회하지 않도록 서버에서 검증.
- FullText 유사검색 정의, OR/AND 대상 필드, G/S/E 상하위 관계와 정렬 기준.
- 기간 제한과 다운로드 크기·건수·파일 보존시간·취소/재시도 정책, XLSX 분할 기준.
- 웹 개발 수용 여부, LMS 필수 기능 범위, SSO, 영어 지원, 운영·유지보수 담당.
- Contributor 초대 및 반입 절차, 고객의 최종 승인 범위.

날짜 선택은 중간 대화상자·적용 버튼 없이 바로 반영합니다. 자주 쓰는 상대 기간은 한 번 클릭하는 버튼으로 제공합니다. 다운로드·저장된 검색조건·연결 상태에도 같은 SK 색상, 패널, 글자 크기와 상태 표시를 적용합니다.
