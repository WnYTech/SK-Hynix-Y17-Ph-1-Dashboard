# 요구사항 추적표

작성 기준: 2026-10-01. 사용자가 제공한 이미지 3장(추가 요구사항, ARC LMS, M14N Acell LogViewer) 및 전달받은 협의 내용을 함께 반영했습니다.

최신 작업 지시: **하나의 LMS로 구축. Acell/ARC 모드는 제공하지 않습니다. TypeScript / React / FastAPI로 프레임부터 구축하며 더미데이터 생성·적용은 제외합니다.** 이미지에 기재된 더미데이터 요구보다 이 지시가 우선합니다.

납기 목표: **2026-10-14(수)**. 제공 채널은 지정 GitHub 저장소이며, 외부 공개 저장소 접근 및 고객 Contributor 방식의 전달을 전제로 합니다. 계정 초대, 저장소 공개 설정 변경, 실제 반입·배포는 이번 프레임 작성에 포함하지 않습니다.

## 우선순위 및 범위

1. 생산 시스템별 / 로그 종류별 **기간 지정 조회와 다운로드**. 수백 MB 로그에서 발생하는 타임아웃이 우선 해결 대상입니다.
2. ELIS의 Space 구분과 별개로 **허용된 연관 시스템의 로그를 함께 탐색**하는 흐름.
3. 기존 화면의 요구사항을 하나의 LMS로 통합한 이식성 높은 웹 프레임.

사업 측 의견은 기존 LMS 모든 기능의 필수 재현 여부와 웹 유지보수 범위를 먼저 합의해야 한다는 것입니다. 이미지의 ‘파악된 기능 필수 구현’ 문구만으로 최종 범위가 확정되었다고 간주하지 않습니다. 이 문서는 프레임과 추후 연동·협의 항목을 분리합니다.

## 단일 LMS 화면

참고 이미지의 Acell LogViewer와 ARC LMS는 요구사항의 출처입니다. 제품 화면·검색조건·API 요청을 두 모드로 나누지 않습니다.

| 구분            | 통합 구성                                                                                                                                                   |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기본 검색조건   | Time, Fab, System, Process, Core/Biz, G 트랜잭션 ID, 트랜잭션 키                                                                                            |
| 상세 검색조건   | 트랜잭션명, 클래스명, 서버, SEQ, G 트랜잭션 SEQ, E/S 트랜잭션 ID, 로그 종류, OR, AND, Full Text                                                             |
| 로그 종류       | 실제 메타데이터의 제안 목록에서 선택하거나 공백으로 구분한 값을 직접 입력                                                                                   |
| 상세 탭         | 단일 로그 / 트랜잭션 전체 로그 / 서비스(S) / 이벤트(E) / 글로벌(G) 로그                                                                                     |
| 결과 컬럼       | No, Datetime, 시스템, 프로세스, 서버, SEQ, 로그 종류, 트랜잭션명, 클래스명, 트랜잭션 키, G 트랜잭션, G SEQ, E 트랜잭션, S 트랜잭션, LOT, EQP, 소요(ms), MSG |
| 저장된 검색조건 | 모든 필드를 함께 저장. 이전 저장값의 모드 구분은 무시하고 실제 입력값과 기간을 복원                                                                         |

G 트랜잭션 ID와 일반 트랜잭션 키, SEQ와 G SEQ는 실제 매핑이 확인되기 전까지 서로 다른 필드로 보존합니다. System 전체 검색에는 G 트랜잭션 ID가 필요하고, 일반 키만 사용할 때는 개별 System을 지정합니다.

ARC 이미지의 `EOP`, Acell 이미지의 `EQP` 표기를 공통 `EQP`로 가정했습니다. 실제 의미가 서로 다르면 필드를 분리해야 합니다. 제목 없는 컬럼에는 임의 의미를 부여하지 않았습니다.

## 연동 전에 필요한 정보

- Elasticsearch / Kibana 버전, 접속 경로, 인증 방식, 인덱스 또는 alias 목록.
- 운영 로그와 동일한 스키마의 비식별화 샘플, 시간·MSG·S/E/G ID·ARC 키 매핑.
- Fab / System / Process / Core·Biz / 로그 종류 코드표와 선택값 종속 규칙.
- 시스템 간 조회 권한과 Space별 접근 정책. 웹에서 권한을 우회하지 않도록 서버에서 검증.
- FullText 유사검색 정의, OR/AND 대상 필드, G/S/E 상하위 관계와 정렬 기준.
- 기간 제한과 다운로드 크기·건수·파일 보존시간·취소/재시도 정책, XLSX 분할 기준.
- 웹 개발 수용 여부, LMS 필수 기능 범위, SSO, 영어 지원, 운영·유지보수 담당.
- Contributor 초대 및 반입 절차, 고객의 최종 승인 범위.
